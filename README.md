documentation: https://restful-booker.herokuapp.com/apidoc

## 2. Tools
- Java 21
- Spring Boot
- Gradle

- JUnit 5

- Lombok

## 3. Test execution

### 3.0 Configuration (profiles and env vars)
Defaults are configured for the public Restful Booker demo service.

**Option A: Select environment via Spring profile**
Profiles are defined in:
- `src/main/resources/application-qa.properties`
- `src/main/resources/application-dev.properties`

Run locally with a selected profile:
- macOS/Linux (zsh/bash): `SPRING_PROFILES_ACTIVE=dev ./gradlew test`
- Windows PowerShell: `$env:SPRING_PROFILES_ACTIVE="dev"; ./gradlew test`
- Windows cmd: `set SPRING_PROFILES_ACTIVE=dev && gradlew test`

(Replace `dev` with `qa` to use the QA profile.)

**Option B: Override via environment variables**
- `BOOKER_BASE_URL`
- `BOOKER_USERNAME`
- `BOOKER_PASSWORD`

### 3.1 Regression test execution
`./gradlew test`
<br/>

or

`./gradlew test -PincludeTags=regression`

Will execute full regression

### 3.2 Running arbitrary tests
It is possible to run any test or tests which are annotated by JUnit5 tags.
<br/>
To run tests which include specific tag e.g. `"debug"`, annotate test/s by `@Tag("debug")`
(or `@Debug` - prepared alias for investigation), then run the following command:
`./gradlew test -PincludeTags=debug`
<br/>

#### 3.2.1 Running tagged tests on a selected environment (Spring profile)
Use `SPRING_PROFILES_ACTIVE` together with the Gradle command.

Examples (tag: `debug`, profile: `dev`):
- macOS/Linux (zsh/bash): `SPRING_PROFILES_ACTIVE=dev ./gradlew test -PincludeTags=debug`
- Windows PowerShell: `$env:SPRING_PROFILES_ACTIVE="dev"; ./gradlew test -PincludeTags=debug`
- Windows cmd: `set SPRING_PROFILES_ACTIVE=dev && gradlew test -PincludeTags=debug`

## 4. View the report (Allure)

### 4.1 Local run (generated by Gradle)
After test execution, generate the report and open it:
- `./gradlew allureReport`
- `./gradlew allureServe`

### 4.2 CI/CD artifact (downloaded from GitHub Actions)
The workflow uploads **`build/reports`** as an artifact named `reports`.

After downloading and unzipping the artifact:
1. Open a terminal **in the unzipped `reports/` directory** (this directory corresponds to `build/reports`)
2. Run:
   `allure open allure-report/allureReport`

Notes:
- The `allure-report/allureReport` folder is the generated HTML report produced by the Gradle Allure plugin.
- If you downloaded only raw results (`allure-results`) instead of the generated report, you must generate the report first (e.g. `allure generate ...`).
